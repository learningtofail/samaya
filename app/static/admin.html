About this tab

An event is anything the bot posts on a schedule. Give it a duration and it also becomes a Discord Scheduled Event and shows on the public calendar. Leave the duration off and it is a message only.

  • Repeating events ask what you are editing: just one date, this date and every later one, or all of them.
  • Reminders post to the audiences each alliance uses by default. Untick an audience on the event to skip it, or tick another to add it. Alliances and audiences that share a channel get one combined message.
  • Reminder messages. Each reminder can have its own text, such as "Starting now!" for the reminder at the start. A reminder with no text posts the event message. A reminder's own text goes to every alliance and replaces an alliance's own message for that reminder.
  • Leadership only events never create a Discord Scheduled Event and never appear on public pages.
  • Deleting an event also removes its Discord events. Deactivating stops all posting but keeps the event.

About this tab

Every Discord post the engine makes or tries to make, one row each. Upcoming lists pending and sending posts, soonest first. Past lists posted, failed and cancelled posts, newest first, within the look-back window. The Detail column says why a post failed or what happened.

  • Retry puts a failed post back in the queue. It only works while the event has not started and is not cancelled.
  • Needs attention means there are errors in the last 7 days or a post has waited more than 5 minutes.

Attendance groups

Attendance groups
GroupRuleEventsActions
About this tab

A type is a starting point for new events: a color and the duration, repeat interval, message, reminders and role mention a new event of that type begins with. Changing a type never changes events that already exist.

Types belong to a kingdom and are shared by every alliance in it. A type that events still use cannot be deleted. Creating and editing types needs kingdom coordinator access.

Notify me roles set here are the fallback for events of the type that have no role of their own. Attendance groups mark events a player cannot attend together. With "one role at a time" a second Notify me tap offers a Switch. "Attend one per day" or "per week" (weeks start on Monday, UTC) makes I'm in refuse a second event in the window until the player taps Switch. Headcounts are advisory and visible to leaders only. Samaya never deletes a Discord role, and creating or assigning roles needs the Manage Roles permission with the bot role above the Notify me roles.

Polls

About this tab

A poll proposes two to six UTC start times. Samaya posts it to the audiences you choose, with one button per time. Players tap every time that works for them and tap again to take a vote back. The counts in the Discord message update as people tap.

Samaya stores a one-way code for each voter, never their Discord ID, and shows counts only, never names. Counts are advisory: anyone who can see the channel can vote, and one person with several accounts can skew them. You decide the winner.

A poll closes by itself after the time you set (up to 14 days) or when you close it. Closing removes the buttons and writes the final tally. Nothing changes on the schedule on its own: after closing, use Move occurrence (for a poll linked to an occurrence) or New event to apply a time. At most three polls per alliance can be open at once. Polls are kept for 90 days. Use Suggest slots in the new poll form to fill in free times from the Insights tab's finder.

    About this tab

    Insights reads what Samaya already stores and changes nothing. The heatmap counts occurrences of active, not cancelled events by weekday and UTC hour over the look-ahead window; a moved occurrence counts at its new time. Overlaps lists events whose times actually intersect. An event with no duration counts as 30 minutes. Events that merely touch do not overlap.

    Find a free slot proposes up to five start times on a quarter-hour grid that do not collide with any event you can see (or only the alliances you tick; kingdom-wide events always count). It prefers the times furthest from the nearest event and never returns two slots that overlap each other.

    Reminder delivery shows, per day or per destination, how many reminders were due, posted and failed, and how late the posted ones were (median and 95th percentile). Merged sends count once. Gift code coverage is a per-alliance percentage from the latest runs. You see the same alliances you can see everywhere else, and nothing here is public.

    About this tab

    Paste a code and Samaya redeems it for every player on the chosen alliances' lists, one at a time. A run is kept going by the server, so you can close this page. Players who already redeemed the same code in an earlier run are not asked again.

    A run stops on its own if the code has expired, is wrong, or has reached its claim limit, if the game server cannot be reached or refuses Samaya, or if its answers stop making sense, which usually means the game changed its API. "Wrong kingdom" means the game rejected that player's ID and kingdom number together; fix the number on the Players tab and run the code again.

    Samaya talks to the game's own redemption endpoint with its own name in the request, not pretending to be a browser. The game could still block it. Results are kept for 90 days.

    To switch this on, the server administrator sets KS_GIFTCODE_SIGN_KEY in .env and restarts the app.

    Feedback

    View

    About this tab

    What the community sent through the public feedback page. Open a ticket to see its details and the private contact the submitter left.

    • Responses are public. Anyone on the feedback page can read them, under your display name or "Team".
    • Dismiss hides a ticket from the public page without deleting it, and Restore brings it back. Only a superadmin can delete one for good.
    • Edit fixes the title, text or type, for example to remove personal details. The submitter is not told.
    • Done and declined tickets are grouped as Archived.
    • Tags, checklists and internal notes are for the team only and never reach the public page. A ticket can carry up to 8 tags, 50 checklist items and notes written in Markdown. The Tag filter applies to both List and Board.
    • Export downloads every ticket, dismissed ones included, as one JSON file or as a zip of Markdown files. Submitter contact details are left out unless you tick the box. Each export is recorded in the audit log.
    • Column limits (superadmin, Board view) cap how many tickets a column should hold. Moving a card into a full column asks you to confirm, and the override is recorded in the audit log. The status menu in List view is not limited.
    • Board shows one column per status. Use a card's Move menu (keyboard and touch), or drag it with a mouse. Moving a card changes its public status, and a move into Done or Declined asks first because it closes voting. Dismissed tickets are not on the board; use List to see them.
